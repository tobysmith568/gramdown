# Code style

- Don't inline a function call as an argument to another call (e.g. `outer(inner(x))`). Assign the inner call's result to a well-named variable first, then pass that variable to the outer call. This applies to `await`ed calls too. It makes the intermediate value easier to read and gives a distinct line to set a debugger breakpoint on.
- Always use braces around `if`/`else` bodies, even for a single statement (e.g. `if (!x) return;` should be `if (!x) {\n  return;\n}`). Prettier (printWidth 100) collapses a brace-less multi-line `if` back onto one line on save, so braces are the only form that survives formatting consistently.
- Don't use SHOUTY_SNAKE_CASE for constants in TypeScript/JavaScript. Every `const` is already immutable, so there's no need to case it differently from any other variable — use ordinary `camelCase` (e.g. `const maxRetries = 5;`, not `const MAX_RETRIES = 5;`).
- Order top-level declarations in a file with the public/exported ones first, private helpers after: exported consts/types, then non-exported consts, then exported functions, then the non-exported helper functions they call. The one exception is a genuine evaluation-order requirement — a top-level `const` built eagerly (e.g. an object literal or `Array.from(...)` that runs at module load) must have its dependencies declared above it, since that's a hard JS rule, not a style choice. A helper referenced only *inside* another function's body has no such constraint, since that reference isn't evaluated until the function is actually called later — those should move below the exported function that uses them.

# Design

- Don't export a private helper purely to make it unit-testable. If a helper's behavior is intricate enough to deserve its own direct tests (rather than being adequately covered through the public function that calls it), that's a signal it's a distinct concern from the module it's currently sitting in — move it to whichever module already owns that concern (creating one if none fits), export it there, and test it there. The test boundary should follow the module boundary, not force a new one open.
